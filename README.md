# VAE-SPC: Variational Autoencoder and Statistical Process Control for IoT Anomaly Detection

**VAE-SPC** is a research framework for **unsupervised anomaly detection in IoT network traffic** that combines **Variational Autoencoders (VAE)**, **learned categorical embeddings**, and **Statistical Process Control (SPC)**.

The framework learns the normal behavior of benign network flows and monitors deviations in both the **latent representation** and the **reconstruction space** to identify potentially anomalous or botnet-related traffic.

The project is designed for high-dimensional flow-level network data containing a mixture of numerical and high-cardinality categorical variables such as IP addresses, MAC addresses, ports, protocol information, and application metadata.

---

## Overview

Traditional anomaly detection techniques can struggle with IoT network traffic because flow records usually contain:

* high-dimensional numerical variables;
* categorical variables with very high cardinality;
* nonlinear relationships;
* temporal dependencies;
* highly heterogeneous device behavior;
* strongly imbalanced benign and malicious traffic.

VAE-SPC addresses these challenges by combining representation learning and statistical monitoring.

The general pipeline is:

```text
Network traffic
      │
      ▼
Flow extraction
      │
      ▼
Parquet flow dataset
      │
      ▼
Preprocessing
 ├─ Numerical scaling
 ├─ Categorical encoding
 └─ Temporal train/test split
      │
      ▼
Learned categorical embeddings
      │
      ▼
β-Variational Autoencoder
      │
      ├───────────────┐
      ▼               ▼
Latent space      Reconstruction
      │               │
      ▼               ▼
     T²              SPE
      │               │
      └───────┬───────┘
              ▼
     Statistical Process
          Monitoring
              │
              ▼
       Anomaly detection
```

## Dataset

The experimental data used in this project are derived from the **Aposemat IoT-23 dataset**, developed and published by the **Stratosphere Laboratory**.

**IoT-23** is a labeled network-traffic dataset designed for cybersecurity research involving Internet of Things devices. It contains traffic generated by both **benign IoT devices** and devices infected with different families of IoT malware.

The original dataset contains:

| Characteristic      | Description                              |
| ------------------- | ---------------------------------------- |
| Total scenarios     | **23**                                   |
| Malicious scenarios | **20**                                   |
| Benign scenarios    | **3**                                    |
| Traffic type        | Real IoT network traffic                 |
| Capture period      | **2018–2019**                            |
| Original format     | PCAP and labeled Zeek network flows      |
| Environment         | Controlled IoT network environment       |
| Institution         | Stratosphere Laboratory / CTU University |

The malicious scenarios include traffic associated with several IoT malware families, including examples such as:

* Mirai
* Torii
* Hide & Seek
* Hajime
* and other IoT malware families.

The benign scenarios were generated using real IoT devices, including an **Amazon Echo**, **Philips Hue smart lamp**, and **Somfy Smart Door Lock**.

## Methodology

### 1. Flow-level representation

The framework operates on network flows rather than individual packets.

The input representation contains both **categorical** and **numerical** information.

Examples of categorical variables include:

| Group            | Examples                                                                                          |
| ---------------- | ------------------------------------------------------------------------------------------------- |
| Network identity | `src_ip`, `dst_ip`, `src_mac`, `dst_mac`                                                          |
| Ports            | `src_port`, `dst_port`                                                                            |
| L3/L4 metadata   | `protocol`, `ip_version`, `vlan_id`, `tunnel_id`                                                  |
| Application      | `application_name`, `application_category_name`                                                   |
| TLS / HTTP       | `requested_server_name`, `client_fingerprint`, `server_fingerprint`, `user_agent`, `content_type` |

Numerical features include statistics related to:

* flow duration;
* packet counts;
* transmitted bytes;
* packet-size distributions;
* packet inter-arrival times;
* directional traffic statistics;
* TCP flag counts.

## Preprocessing

The preprocessing pipeline is implemented in [`preprocess.py`](preprocess.py).

To support large network datasets, the preprocessing procedure reads Parquet files in batches instead of loading the complete dataset into memory.

Two passes over the data are performed.

### Pass 1 — Fit

The first pass:

1. identifies the vocabulary of every categorical variable;
2. fits the numerical scaler;
3. determines categorical cardinalities;
4. determines the embedding configuration.

Numerical variables are scaled using:

```text
MinMaxScaler → [0, 1]
```

### Pass 2 — Transform

The second pass:

1. converts categorical values into integer indices;
2. transforms numerical variables;
3. stores compact `int32` and `float32` arrays;
4. sorts observations according to their flow timestamp.

Unknown or missing categories are assigned index:

```text
0
```

The observations are then split chronologically into:

```text
80% Training
20% Testing
```

No random train/test shuffle is performed during this split, reducing the risk of **temporal data leakage**.

Generated preprocessing artifacts include:

```text
processed/
├── train.npz
├── test.npz
├── train_timestamp.npy
├── test_timestamp.npy
├── metadata.json
├── scaler.pkl
└── vocabs.pkl
```

## Learned Categorical Embeddings

One of the main characteristics of the framework is that categorical variables are **not represented using conventional one-hot encoding**.

Instead, every categorical variable has its own trainable embedding table.

Conceptually:

```text
src_ip ───────► Embedding(src_ip)
dst_ip ───────► Embedding(dst_ip)
src_port ─────► Embedding(src_port)
protocol ─────► Embedding(protocol)
application ──► Embedding(application)
...
```

The resulting embeddings are concatenated with the scaled numerical variables:

```text
X =
[
  numerical features,
  embedding(src_ip),
  embedding(dst_ip),
  embedding(src_mac),
  ...
]
```

This complete vector becomes the input of the Variational Autoencoder.

For very high-cardinality categorical variables, the implementation supports **sparse embeddings** and `SparseAdam` optimization.

## β-Variational Autoencoder

The main model is implemented in [`model.py`](model.py) using:

* **PyTorch**
* **Pyro**
* Stochastic Variational Inference (`SVI`)
* `Trace_ELBO`

The encoder approximates:

$$
q_\phi(z|x)
$$

while the decoder models:

$$
p_\theta(x|z)
$$

The latent representation is sampled using:

$$
z = \mu + \sigma \odot \epsilon,
\qquad
\epsilon \sim \mathcal{N}(0,I)
$$

The $\beta$-VAE objective can be represented as:

\[
\mathcal{L}_{\beta}
=
\mathbb{E}_{q_\phi(z|x)}
[
\log p_\theta(x|z)
]
-
\beta
D_{KL}
\left(
q_\phi(z|x)
\parallel
p(z)
\right)
\]

where \(\beta\) controls the trade-off between reconstruction fidelity and latent-space regularization.

## Statistical Process Control

After training the VAE on normal network behavior, the learned representation is monitored using **Statistical Process Control (SPC)**.

Two primary monitoring statistics are considered.

### Hotelling's T²

The T² statistic measures deviations in the learned latent space:

$$
T_i^2 =
(z_i-\bar{z})^T
S_z^{-1}
(z_i-\bar{z})
$$

where:

* \(z_i\) is the latent representation of observation \(i\);
* \(\bar{z}\) is the reference latent mean;
* \(S_z\) is the covariance matrix of the reference latent space.

Large T² values indicate unusual behavior relative to the normal latent representation.

### Squared Prediction Error — SPE

SPE measures the reconstruction residual:

$$
SPE_i =
\lVert x_i-\hat{x}_i \rVert_2^2
$$

Large SPE values indicate observations that cannot be adequately reconstructed from the behavior learned by the VAE.

Conceptually:

```text
                 Network flow
                      │
                      ▼
                     VAE
                ┌─────┴─────┐
                │           │
                ▼           ▼
             Latent     Reconstruction
              space         error
                │           │
                ▼           ▼
               T²          SPE
                │           │
                └─────┬─────┘
                      ▼
              Anomaly detection
```

## Model Training

The main training script is:

```bash
python train_vae.py
```

The current default configuration is:

| Parameter                   |  Default |
| --------------------------- | -------: |
| Epochs                      |     `20` |
| Batch size                  |   `4096` |
| Hidden dimension            |     `50` |
| Latent dimension            |     `10` |
| β                           |    `1.1` |
| Learning rate               |   `1e-4` |
| Sparse vocabulary threshold | `10,000` |

Example:

```bash
python train_vae.py \
    --epochs 25 \
    --batch-size 4096 \
    --hidden-dim 80 \
    --z-dim 30 \
    --beta 1.2 \
    --lr 0.0001
```

CUDA is automatically used when a compatible GPU is available.

## Research Motivation

The central research idea behind VAE-SPC is to combine two complementary paradigms.

### Deep Generative Learning

The VAE learns a nonlinear representation of normal IoT network behavior.

### Statistical Process Control

SPC determines whether subsequent observations remain statistically consistent with the learned reference behavior.

The complete methodology can therefore be summarized as:

$$
\text{IoT Traffic}
\rightarrow
\text{Representation Learning}
\rightarrow
\text{VAE}
\rightarrow
\text{T² / SPE}
\rightarrow
\text{SPC}
\rightarrow
\text{Anomaly Detection}
$$
